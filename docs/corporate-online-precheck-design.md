# ระบบตรวจสอบยอดเงินและเลขบัญชี ก่อนอัปโหลดเข้า Corporate Online

จัดทำ: 2026-10-20 · ต้นแบบ (prototype) อยู่ที่หน้า `/transfer-check`

---

## 1. ปัญหาที่ต้องการแก้

ไฟล์โอนเงินรายการใหญ่ (จ่ายเงินกู้ เงินปันผล/เฉลี่ยคืน คืนเงินหักเกิน สวัสดิการ ฯลฯ)
ถูกเตรียมจาก Excel แล้วอัปโหลดเข้า Corporate Online ของธนาคาร เมื่ออนุมัติแล้ว**เรียกเงินคืนยาก**
ความผิดพลาดที่พบบ่อยและต้องจับให้ได้ก่อนอัปโหลด:

| ความผิดพลาด | สาเหตุทั่วไป |
| --- | --- |
| เลขบัญชีหลักขาด (เลข 0 นำหน้าหาย) | Excel มองคอลัมน์เป็นตัวเลข |
| เลขบัญชีกลายเป็น `1.23E+09` | Excel แปลงเลขยาวเป็นรูปแบบวิทยาศาสตร์ |
| ยอดเงินมีทศนิยมเกิน 2 ตำแหน่ง / ปัดเศษผิด | สูตรคำนวณใน Excel |
| ยอดรวมไม่ตรงกับเอกสารอนุมัติ | แถวตกหล่น/เกิน, คัดลอกผิดช่วง |
| คนเดียวโอนซ้ำ 2 รอบ | คัดลอกแถวซ้ำ, รวมไฟล์หลายชุด |
| ยอด/ชื่อ ไม่ตรงกับระบบสหกรณ์ | พิมพ์ผิด, เลื่อนแถว (แถวขยับทำให้ยอดผิดคน) |

## 2. หลักการออกแบบ

1. **ตรวจในเครื่อง ไม่ส่งข้อมูลออก** — เลขบัญชี/ยอดเงินสมาชิกเป็นข้อมูลอ่อนไหว ประมวลผลบนเบราว์เซอร์ทั้งหมด (ไม่มี API, ไม่บันทึกฐานข้อมูล)
2. **เทียบ 3 ทาง (3-way match)** — ไฟล์อัปโหลด ↔ รายการต้นทางจากระบบสหกรณ์ ↔ ยอดควบคุมตามเอกสารอนุมัติ (จำนวนรายการ + ยอดรวม)
3. **เงินเป็นจำนวนเต็มสตางค์** — ไม่ใช้ทศนิยม float เพื่อไม่ให้ยอดรวมคลาดเคลื่อน 0.01
4. **ตรวจคอลัมน์จากหัวตาราง (header keyword)** — ไม่ fix ตำแหน่งคอลัมน์ และให้ผู้ใช้แก้การจับคู่ได้
5. **ผิดพลาด = ห้ามอัปโหลด, เตือน = ให้คนตัดสินใจ** — แยกระดับชัดเจน
6. **ล็อกไฟล์ด้วย SHA-256** — ไฟล์ที่ตรวจผ่านต้องเป็นไฟล์เดียวกับที่อัปโหลด แก้ไขหลังตรวจแม้ 1 ตัวอักษรค่า hash จะเปลี่ยน

## 3. ขั้นตอนการทำงาน (Maker–Checker)

```
 ระบบสหกรณ์ ──export──▶ รายการต้นทาง.csv ─┐
                                             ├─▶ [หน้าตรวจ /transfer-check] ─▶ ผลตรวจ + SHA-256
 Excel เตรียมโอน ──save as──▶ ไฟล์อัปโหลด.csv ─┘              │
 เอกสารอนุมัติ ──▶ จำนวนรายการ / ยอดรวม (กรอกมือ) ──────────────┘
                                                                │
          ❌ มีข้อผิดพลาด → แก้ไฟล์ → ตรวจใหม่                    │
          ✅ ผ่าน → ผู้จัดทำ (Maker) อัปโหลดเข้า Corporate Online ◀─┘
                 → ผู้อนุมัติ (Checker) ดูผลตรวจ + เทียบยอดรวมบนหน้าจอธนาคาร → อนุมัติ
```

## 4. กฎการตรวจ

### 4.1 รายแถว (ไฟล์อัปโหลด)

| รหัส | ระดับ | เงื่อนไข |
| --- | --- | --- |
| `ACCOUNT_MISSING` | ผิดพลาด | ไม่มีเลขบัญชี |
| `ACCOUNT_SCIENTIFIC` | ผิดพลาด | เลขบัญชีอยู่ในรูป `E+` |
| `ACCOUNT_FORMAT` | ผิดพลาด | มีอักขระที่ไม่ใช่ตัวเลข (ขีด/ช่องว่างตัดทิ้งก่อนตรวจ) |
| `ACCOUNT_LENGTH` | ผิดพลาด | จำนวนหลักไม่ตรงตามธนาคาร (ค่าเริ่มต้น 10 หลัก; ออมสิน/ธอส./ธ.ก.ส. 12 หลัก) — ถ้าสั้นกว่าจะแนะนำว่าอาจเสียเลข 0 นำหน้า |
| `AMOUNT_INVALID` | ผิดพลาด | ไม่ใช่ตัวเลข หรือทศนิยมเกิน 2 ตำแหน่ง |
| `AMOUNT_NONPOSITIVE` | ผิดพลาด | ยอด ≤ 0 |
| `AMOUNT_HIGH` | เตือน | ยอดต่อรายการ ≥ เกณฑ์ (ค่าเริ่มต้น 500,000 บาท ปรับได้) |
| `NAME_MISSING` | เตือน | แถวนี้ไม่มีชื่อ ทั้งที่แถวอื่นมี |
| `DUPLICATE_ACCOUNT` | เตือน | เลขบัญชีเดียวกันมากกว่า 1 แถว |

### 4.2 ระดับชุด (ยอดควบคุม)

| รหัส | ระดับ | เงื่อนไข |
| --- | --- | --- |
| `CONTROL_COUNT` | ผิดพลาด | จำนวนรายการ ≠ เอกสารอนุมัติ |
| `CONTROL_TOTAL` | ผิดพลาด | ยอดรวม ≠ เอกสารอนุมัติ (แสดงส่วนต่าง) |

### 4.3 เทียบกับรายการต้นทาง (จับคู่ด้วยเลขบัญชี)

| รหัส | ระดับ | เงื่อนไข |
| --- | --- | --- |
| `NOT_IN_SOURCE` | ผิดพลาด | มีในไฟล์อัปโหลด แต่ไม่มีในต้นทาง |
| `MISSING_FROM_UPLOAD` | ผิดพลาด | มีในต้นทาง แต่ไม่มีในไฟล์อัปโหลด |
| `AMOUNT_MISMATCH` | ผิดพลาด | ยอดรวมต่อบัญชีไม่ตรง (บัญชีซ้ำเทียบยอดรวม จึงรองรับการแบ่งจ่าย) |
| `NAME_MISMATCH` | เตือน | ชื่อไม่ตรง หลังตัดคำนำหน้า (นาย/นาง/นางสาว/น.ส./Mr. ฯลฯ) และช่องว่าง |

## 6. ข้อจำกัดของต้นแบบ และแผนต่อยอด

**ระยะที่ 1 (ต้นแบบนี้)** — รับ CSV/TXT, ตรวจตามกฎข้อ 4, ไม่เก็บข้อมูล

**ระยะที่ 2**
- อ่าน `.xlsx` โดยตรง (ไม่ต้อง Save as CSV) — ลดปัญหาเลข 0 หายตั้งแต่ต้นทาง
- รองรับ **รูปแบบไฟล์ของธนาคารจริง** (เช่น fixed-width ที่มี header/detail/trailer record): ตรวจความยาวแต่ละ record, ยอดรวมใน trailer ตรงกับผลรวม detail, วันที่มีผล (effective date) ไม่เป็นวันหยุด
- ตรวจ **Check digit / ชื่อบัญชีจริงกับธนาคาร** — ทำได้เฉพาะเมื่อธนาคารมีบริการตรวจสอบชื่อบัญชี (Account Name Inquiry) ให้ใช้; Corporate Online บางธนาคารแสดงผลนี้หลังอัปโหลด ให้ Checker ดูที่หน้าจอธนาคารแทน

**ระยะที่ 3 (เชื่อมระบบสหกรณ์)**
- เทียบกับ `MemberRoster` (เลขสมาชิก ↔ เลขบัญชีรับเงินที่ลงทะเบียนไว้) — บัญชีที่**ไม่ใช่บัญชีที่สมาชิกลงทะเบียน**เป็นสัญญาณเสี่ยงทุจริต ควรเป็นระดับผิดพลาด
- กันโอนซ้ำข้ามชุด: เก็บ hash ของ (เลขบัญชี, ยอด, งวด) ของชุดที่อนุมัติแล้ว เตือนเมื่อพบซ้ำในชุดใหม่
- บันทึก audit log (ใครตรวจ เมื่อไร SHA-256 อะไร ผลเป็นอย่างไร) และแจ้งผลผ่าน LINE ถึงผู้อนุมัติ

## 7. วิธีใช้งาน

1. Export รายการจากระบบสหกรณ์เป็น CSV (รายการต้นทาง)
2. ใน Excel ตั้งคอลัมน์เลขบัญชีเป็น **Text** แล้ว Save as **CSV UTF-8** (ไฟล์อัปโหลด)
3. เปิด `/transfer-check` เลือกไฟล์ทั้งสอง ตรวจการจับคู่คอลัมน์ กรอกจำนวนรายการและยอดรวมจากเอกสารอนุมัติ
4. แก้จนไม่มี ❌ — ทบทวนทุก ⚠️ — ดาวน์โหลดผลตรวจแนบเอกสาร
5. อัปโหลดไฟล์**เดิม**เข้า Corporate Online (ห้ามเปิดแก้ไขหลังตรวจ) — ผู้อนุมัติเทียบจำนวนรายการ/ยอดรวมบนหน้าจอธนาคารกับผลตรวจอีกครั้งก่อนอนุมัติ
